# 工作区方案 v2（精简版）

> 目标：工作区分级 + 可复用工具沉淀，让以后做项目少探索、少重复造轮子 → 省 token
> 原则：长期可维护、结构简单、规则少而硬

---

## 一、结构

```
D:\DSH_WorkSpace\
├── .git\                 ← 空目录，只做一件事：钉住工作区根（见第四节）
├── AGENTS.md             ← 唯一常驻规则（约 55 行）
├── README.md             ← 给人看的一页说明
├── 输入资料\              ← 原始材料，只读
├── 输出结果\              ← 非项目任务的成品
│   └── HISTORY.md
├── _Toolbox\             ← 可复用工具（本工作区最重要的资产）
│   ├── INDEX.md
│   └── <工具名>\          ← README.md + 入口脚本 + 依赖
├── _scratch\             ← 一次性试验，随时可删
└── <项目名>\              ← 长期项目，自带 AGENTS.md
```

一共 **1 份常驻规则 + 2 个索引 + 1 份说明**。就这些。

## 二、根 AGENTS.md（可直接落地）

```markdown
# 工作区基线

## 规则优先级
系统/开发者指令 与 用户当前指令 > 子目录 AGENTS.md > 本文件。更具体的规则优先。

## 目录职责
| 目录 | 放什么 | 约束 |
|---|---|---|
| 输入资料/ | 原始材料 | 只读：可 read/glob/grep；禁止 write/edit/删除/重命名/移动/重定向写入 |
| 输出结果/ | 非项目任务的成品 | 一个任务一个子目录，登记 HISTORY.md |
| _Toolbox/ | 跨项目复用工具 | 一个工具一个目录，登记 INDEX.md |
| _scratch/ | 一次性试验 | 子目录用 YYYYMMDD-简称/ |
| <项目名>/ | 长期维护的项目 | 自带 AGENTS.md |

## 产出归属（按顺序判定，第一条命中即止）
1. 要长期维护、会反复改 → 项目目录
2. 一次性交付、事后要能找到 → 输出结果/<任务简称>/
3. 只是过程、无交付价值 → _scratch/YYYYMMDD-<简称>/
4. 不确定 → _scratch/，并在回复里说明原因

## 命名
- 用中文短语，2–6 字；不带日期（_scratch 例外）、不带"最终版/副本/新建/最新"
- 一个任务的产物集中在一个子目录，不超过 8 个文件
- 临时试验目录：YYYYMMDD-简称/

## 工具复用（本工作区的主要目的）
- 任务结束前问一次：这次的逻辑以后还会不会用？
- 会 → 满足以下全部条件才提取到 _Toolbox/<工具名>/：
  能独立运行、无硬编码路径、有明确入口（支持 --help）、
  目录内有 README（用途/输入/输出/依赖/一条示例命令）
- 提取或修改后，往 _Toolbox/INDEX.md 追加一行（只追加，不重写）
- 开工前先看 INDEX.md，已有能用就别重写

## 硬约束
- 输入资料/ 只读（定义见上表）
- 根目录只放 AGENTS.md、README.md 和固定目录，不放任何任务文件
- 目录嵌套不超过 2 层
- 不自行修改任何 AGENTS.md；需要改就提建议，等人确认

## 省 token 纪律
- 先一条命令列目录（名字/大小/时间），再决定读什么
- 大文件先 grep 定位行号，再 read 指定片段
- 相互独立的操作在同一步并行发起
- "找出所有…""排查为什么…"这类多轮搜索任务交给子代理，只回结论
- 一个任务一个会话，长会话及时收尾

## 收尾
1. 文件在对的目录
2. 索引已追加（HISTORY.md / INDEX.md）
3. 回复用一句话说明：放在哪、怎么用

## 盘点（仅在用户明确要求时执行）
- 一条命令列出 _scratch/ 与 输出结果/ 下各子目录的名字、最后修改时间、大小
- 候选规则：_scratch 下超过 30 天未改动；输出结果 下没有登记进 HISTORY.md 的
- 输出一张表 + 每条一句理由，并给出可选的清理命令
- 不执行删除或移动，等人决定

## 静态性
本文件不写日期、进度、计数等会变化的内容。
```

约 55 行 / 1.6 KB。一次会话注入一次，约 500 token。

## 四、唯一必须做的技术前提：`.git` 空目录

DSH 找规则文件的规则是：**项目根 = 从当前目录向上第一个含 `.git` 的目录；找不到就用当前目录**，然后只加载"项目根 → 当前目录"这条链。

所以缺 `.git` 会出现这种情况：

| 场景 | 实际加载 |
|---|---|
| 工作目录在根 | 根 AGENTS.md（正常） |
| 工作目录切到 `输出结果/` 或某个项目子目录 | **根 AGENTS.md 整份消失**，"输入资料只读"当场失效 |

本机没装 git，但加载器只检查 `.git` 这个路径**存不存在**，不校验它是不是真仓库。所以在工作区根建一个空的 `.git\` 目录就够了，零依赖。以后装了 git，直接 `git init` 会被正常接管。

## 五、相对你原版的改动

| 改动 | 原因 |
| :--- | :--- |
| 6 份 AGENTS.md → 1 份 + 项目各自一份 | 全部规则仅 4.2 KB，而单链预算是 64 KB；分成 6 份的代价是每次任务多 1–2 次读文件、且子目录规则要等"触达"才注入，**第一次写入时规则还没被看见** |
| 新增 `.git` 空目录 | 否则切换工作目录时规则链会断（第四节） |
| 修正规则优先级顺序 | 原句自相矛盾（"本文件优先"和"更具体优先"并存） |
| `_Toolbox` 门槛改成可验证条件 | "被使用 ≥2 次""成本低于重写"无法查证，等于没有判据 |
| 砍掉 `_trash/`、`status` 标记、哈希校验 | 增加日常维护负担，违背"简洁"；盘点用日期 + 修改时间就够判断 |
| 砍掉独立的项目模板文件 | 三条字段写在 README 里就够，少维护一个文件 |
| 清理改成"一条命令 + 表格 + 30 天规则" | 原方案要 agent 读内容判断"临时/不确定"，30 个目录就是几十次读取、上万 token，还两次结论不一致 |
| `_scratch` 用日期前缀 | 日期就是最便宜的元信息，盘点时不用看 mtime、不用读内容 |

## 六、落地清单

1. 建 `.git\`（空目录，内含一行说明的 txt 防止被当空目录清掉）
2. 写 `AGENTS.md`（第二节全文）、`README.md`
3. 建 `输入资料\`、`输出结果\`、`_Toolbox\`、`_scratch\`
4. 写 `输出结果\HISTORY.md`、`_Toolbox\INDEX.md`
5. 验收：新开一个会话，确认根规则被加载；再把工作目录切到子目录，确认根规则**仍然在**

第 5 步是唯一容易被漏测、又最关键的一步。
