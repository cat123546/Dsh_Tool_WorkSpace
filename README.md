# 工作区说明

## 这是什么
一个长期使用的个人工作区。按"过程 → 成品 → 资产"分级存放，目的是以后做项目时少探索、少重复造轮子。

## 五个区
- `输入资料/` —— 原始材料，只放不改
- `输出结果/` —— 非项目任务的成品，一个任务一个子目录
- `_Toolbox/` —— 可复用的工具，一个工具一个目录
- `_scratch/` —— 一次性试验，随时可删
- `<项目名>/` —— 长期维护的项目，自带 AGENTS.md

## 日常
把要处理的东西放进 `输入资料/`，把需求告诉 agent。产物落到 `输出结果/<任务简称>/`，并在 `HISTORY.md` 登记。

## 一次任务的标准流程

```
① 你：普通文件丢 输入资料/，敏感文件丢 输入资料/敏感/
② 你：说需求（顺带说个任务名更好；不说我从文件名提）
③ 我：列两处文件 → 建 输入资料/<任务>/ → 归类移动 → 报清单
④ 我：敏感件脱敏 → _scratch/<任务>-处理/脱敏/（只回统计，不回原文）
⑤ 我：普通件直接读，敏感件读脱敏版，两类合在一起加工
⑥ 我：产出写 输出结果/<任务>/，登记 HISTORY.md
⑦ 我：有 <类型_序号> 占位符就还原成人名/单位名再交付
⑧ 对照表留在 _scratch，盘点时随目录一起清
```

**失败处理**：单个文件打不开不中断任务；脱敏残留不为 0 就停下来查；还原不出来的占位符列出来给人判断，不猜。

## 两种脱敏方式

| 方式 | 你怎么做 | 适合 |
| :--- | :--- | :--- |
| **手动** | 双击 `脱敏.cmd`，把文件夹拖进去 | 想自己跑、不打扰会话 |
| **自动** | 直接说需求，我建目录 + 归类 + 脱敏 + 加工 | 日常最省事 |

两种走同一套脚本和规则，结果一样。

## 敏感文件怎么放

**你不用建任务目录**，只做一次分类动作：

```
输入资料/
├── 普通文档            ← 直接丢根目录
└── 敏感/               ← 敏感文档丢这里
```

我收到需求后会建 `输入资料/<任务>/`，把文件归位，并建 `敏感/` 子目录。下次任务时这两处是空的，只剩历史任务子目录，不会串。

跨任务长期要藏的东西（密钥、账号）不要放工作区，放工作区外。

## 新建项目
建 `项目名/`，放一个 `AGENTS.md`，至少写三行：

```
- 输入格式：
- 产物出口：
- 验证/测试命令：
```

## 清理
不需要定期维护。想清理时说一句"盘点一下 _scratch 和 输出结果"。

## 注意
agent 的行为规则在 `AGENTS.md`。改规则请自己动手，别让 agent 改。

## 隐藏文件
`.git/` 是空目录（内含一份说明），作用只有一个：让工具把 DSH_WorkSpace 识别为工作区根。将来装了 git 可直接 `git init` 接管，不必先删它。

## 一个容易忘的坑（2026-11 记录）
工具判断"工作区根"的方式是：从当前目录向上找**最近一个含 `.git` 的目录**，找不到就用当前目录。然后只加载"根 → 当前目录"这条链上的 AGENTS.md。

所以：**如果某个项目目录自己带了 `.git`**（例如 clone 了别人的仓库、或你给某个项目单独 `git init`），在那个项目里工作时，工具会把该项目当成根，**工作区根的 `AGENTS.md` 就不再加载**——"输入资料只读""产出归属"这些约束会静默失效，不报错，很容易忘。

两个补救办法，任选其一：

1. 把真正的红线（输入资料只读）另抄一份到用户级全局规则 `C:\Users\CAT\.dsh\AGENTS.md`。这条链不受项目根影响，永远加载。
2. 或者别让项目单独带 `.git`，整个工作区共用一个版本控制。

判断有没有踩坑的方法：在该项目目录里开一个会话，问 agent"输入资料目录有什么约束"。答不出来就是断了。
