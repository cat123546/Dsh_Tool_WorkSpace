# 提名判据

收尾时按这份判据过一遍，**只读 `输出结果/<任务>/候选.md`，不重新扫项目、不读脚本正文**。

## 第一步：四道确定性检查（全过才继续）

| # | 检查 | 怎么查 | 不过就 |
| :--- | :--- | :--- | :--- |
| 1 | 无绝对路径 | 搜 `D:\` `C:\` `/home/` `/Users/` | 标「可参数化」，进观察区 |
| 2 | 无项目专属**知识** | 代码里有没有写死「只有本项目才懂的判断」：页码到图名的映射、特定文档的章节结构、某单位的业务规则 | **淘汰**——改造等于重写领域内容 |
| 2b | 输入/环境硬编码 | 写死的路径、ID、文件名，属于「换个人用就该换」的值 | 不算淘汰，标「可参数化」进观察区 |
| 3 | 依赖干净 | 只 import 标准库或通用第三方库，不 import 项目内模块 | 淘汰 |
| 4 | 有入口 | 有 argparse 或 `__main__` 保护，`--help` 能跑 | 观察区（补入口是机械活） |

### 检查 2 和 2b 的区别（最容易判错的地方）

| 类型 | 例子 | 改造难度 | 去哪 |
| :--- | :--- | :--- | :--- |
| 硬编码**输入/环境** | `C:\Users\CAT\.dsh`、两个 session ID、某个 PDF 路径 | 低，改成参数 | 观察区 |
| 硬编码**领域知识** | 「第 4 页是四种接地方式、第 5 页是接线图」 | 高，这是人判断出来的 | 淘汰 |

判不准时问一句：**「换别人拿去用，他要改的是值，还是要重新想一遍逻辑？」**
改值 → 观察区；重想逻辑 → 淘汰。

### 处置统一规则

| 检查结果 | 处置 |
| :--- | :--- |
| 命中检查 2（项目专属知识） | **淘汰** |
| 只命中 1 / 2b / 4（输入或入口问题） | 观察区，标注要改哪几处 |
| 命中检查 3（依赖项目内模块） | **淘汰** |
| 四道全过 | 进入第二步「复用证据」，有证据 A 才提名 |

四道都过 → 继续判断。

## 第二步：复用证据（满足其一）

| 证据 | 强度 | 说明 |
| :--- | :--- | :--- |
| **A. 第二次遇到同类需求，又用到它** | ⭐⭐⭐ 最强 | 真实复用已发生，不需要任何统计 |
| B. 代码被其他脚本 import / 调用 | ⭐⭐ | 一条 grep 能查，说明不是纯顶层脚本 |
| C. 本次任务对不同输入跑过 ≥2 次 | ⭐ | 说明是批量工具，不是一次性 |

**注意**：A 之外都只是"线索"，不是"证据"。只要 A 没发生，一律先放观察区。

**不要用"我觉得下次会用"当理由**——这句不算证据。

## 第三步：一句话测试

把用途念给没参与本项目的人听：

- 他能懂 → 过
- 含项目代号、缩写、只有本项目懂的词 → 不过，改写用途描述

## 输出格式（每条候选必须写全）

```markdown
- 文件：文件名
- 用途：一句话（外行能懂）
- 证据：A / B / C（写清是哪条，附实际依据）
- 风险：必须写，写不出说明没检查
- 改造点：要参数化什么、要补什么
- 结论：提名 / 观察区 / 淘汰
```

## 禁止

- 为凑数提名
- 用"想到下次会用"当证据
- 提名后不等拍板就移动、改写或入库
- 收尾时为了列清单重新 glob 整个工作区或读脚本正文

## 三种结果的处置

| 结论 | 谁做 | 动作 |
| :--- | :--- | :--- |
| 提名 | 我列出 | 等你拍板，不动手 |
| 观察区 | 我记一行 | 写进 `_Toolbox/文档/观察区.md`，下次遇到同类需求时优先看这里 |
| 淘汰 | 我说明理由 | 什么都不做 |

## 拍板之后

提取 ≠ 移动。入库前必须做完：

1. 去掉绝对路径，输入输出改成命令行参数
2. 去掉项目专属字面量，必要时改成配置文件或参数
3. 补 `--help` 和使用示例
4. 目录内写 README：用途 / 输入 / 输出 / 依赖 / 一条示例命令
5. 在 `_Toolbox/INDEX.md` 追加一行
6. 真实跑一次，确认能独立运行
